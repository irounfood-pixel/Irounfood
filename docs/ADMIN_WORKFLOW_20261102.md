# 관리자 일상 업무 동선 개편

## 변경
- 메뉴: 승인, 발송캘린더, 주문현황을 앞으로; 출고완료, 재고, 상품을 뒤로 배치.
- 홈은 로고에서 접근. 고객/거래처 승인대기, 오늘/내일 발송, 미입력 송장, 미출고/지연 주문을 해당 조건으로 연결.
- 한국 시간 날짜 기준. 날짜 상세는 해당 월로 이동 후 열림.
- 주문현황에서 출고 처리, 확인 및 중복 클릭 방지. 기존 ship_order_v2 RPC 유지.
- 일반/ML 송장 공통 화면에 실제 수령인(manager_name), 기관, 줄바꿈 배송지, 상품별 수량 표시. 수령인 누락은 명시.
- 고객/ML 승인을 동일 페이지에 표시하고 출처·대기/이력 필터 제공. 기존 묶음 승인·상품 선택·수정·삭제 유지.
- 승인 후 완료 주문 및 거래처 기록은 삭제하지 않음. DB 스키마, 인증, ML 웹앱 주소는 변경하지 않음.
- 목록과 메인에 공통 조건 사용. 방문수령은 송장 작업에서 제외. 저장한 행만 재배치/필터 제외해 다른 입력은 보존.
- 조회 페이지 제한으로 건수/목록이 달라지지 않도록 주문·신청·거래처·배송정보를 페이지 단위 조회.

## 검증
`node tests/admin_workflow.test.cjs`

가상 데이터/DB 어댑터를 이용해 날짜 경계, 메뉴 순서, 건수/목록 조건, 방문수령 제외, 수령인/상품/수량, 승인대기/이력 분리, 1000행 이상 조회, 캘린더 월/날짜 이동, 출고 확인 및 중복 클릭 방지를 검증한다. JavaScript 구문 검증도 포함한다.

운영 주문을 이용한 승인·출고·재고 변경은 검증 목적으로 실행하지 않았다. 작성 시 운영 관리자 브라우저는 로그아웃 상태라 로그인 후 실제 화면 확인은 별도 필요하다.

## 회귀 확인 항목
사진 첨부와 엑셀, ML 상품 매칭/묶음 승인/수정/삭제, 기존 명세표 출력은 기존 함수를 유지한다. 날짜/상태 필터가 적용된 엑셀은 해당 표시 목록만 출력한다.

## 복구
이 변경의 admin.html 커밋을 되돌린다. DB 변경이나 데이터 초기화는 없다.
