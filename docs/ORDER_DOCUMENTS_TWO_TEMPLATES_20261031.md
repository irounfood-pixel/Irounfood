# 주문별 명세표 2종 출력 기능 — 검토 브랜치 (2026-10-31)

## 기능
- 관리자 주문현황·주문처리·출고완료의 **주문 상세** 및 송장·포장박스의 **주문 상세**에서 `명세표 출력` 버튼
- 문서 선택: `거래명세표`(품명·수량·단가·공급가액·부가세·합계) / `납품명세표`(품명·수량, 금액 숨김)
- 공급자 상호·사업자번호·대표자·주소·연락처를 문서 출력 전에 직접 입력. 공급자 정보 저장은 관리자가 체크한 경우에만 해당 브라우저 저장소에 저장
- 공급받는 자·담당자·배송지·출고 예정일·주문 번호 및 상품/수량은 기존 주문 정보에서 채움
- 거래명세표에 상품 현재 판매가를 **초기값**으로 표시하되 단가 수정 및 과세(부가세 포함/별도), 면세 선택 허용. 인쇄 전에 가격·세금 확인 체크 필수
- 별도 출력 창에서 브라우저 인쇄 또는 `PDF로 저장` 사용
- **DB 변경 없음:** 원본 주문, 가격, 재고, 사진, 송장, 거래처별 연동, 운영 페이지에 영향 없음

## 제약 및 안전성
- 주문에 실제 납품 시점의 `unit_price`·`tax_type` 스냅샷이 없으므로 현재 제품 판매가가 반드시 실제 거래가라고 가정하면 안 됩니다. 거래명세표는 출력 전에 단가/과세를 직접 확인·수정합니다.
- 수정된 출력 단가·세금은 주문 원본에 저장되지 않으며 다음 출력에 자동 반영되지 않습니다. 이를 영속 저장하려면 별도 승인된 스키마 변경과 단가 이력 설계가 필요합니다.
- 공급자 사업자번호 등은 실제 정보를 입력해야 하고, 거래명세표는 세금계산서를 대체하지 않습니다.
- 출력 창 팝업 차단 해제가 필요할 수 있습니다.
- 이번 버전은 **주문별 1건 인쇄**입니다. 다중 주문 합산 및 일괄 인쇄는 별도 기능입니다.
- 본 기능은 관리자 인증 이후 관리자 화면에서만 접근하고, 기존 주문 로딩 및 조회권한을 그대로 사용합니다.

## 검증
- JavaScript 문법 및 순수 계산·출력 HTML·HTML escaping·입구 연결 확인.
- 재현 테스트: `node --test tests/order_documents.test.cjs` 또는 `node tests/order_documents.test.cjs`.
- 운영 배포 전 실제 모바일/데스크톱 브라우저에서 거래명세표·납품명세표 각 1건 출력, 과세·면세 혼합 품목, 값 수정, A4 PDF 저장, 기존 주문/재고 불변 확인 필요.
- 운영 DB와 GitHub main은 **이 개발 브랜치를 준비하는 과정에서 수정하지 않았음**.


## 공급자 정보 서버 저장 기능 확장 (2026-10-31)

- 주문문서의 공급자 정보는 `public.document_supplier_profile` 단일 행에 저장. 개별 공급자·계좌 실데이터는 **GitHub에 저장하지 않음**.
- 관리자 로그인 및 `private.is_admin()` 검사를 통과한 사용자만 SELECT/INSERT/UPDATE. anon 권한 철회, RLS 활성화, DELETE 권한 없음.
- 필드: 상호, 사업자등록번호, 대표자, 사업장 주소, 연락처, 업태, 종목, 입금은행/예금주, 계좌번호.
- 관리자 인쇄 양식에서 `공급자 정보 저장`을 명시적으로 선택할 때만 입력값이 DB에 저장됨. 출력은 현재 화면 입력값으로 생성.
- 거래명세표에 업태·종목·입금계좌 표시. 납품명세표에는 업태·종목 표시, 입금계좌 비표시.
- 상품 `order_items.unit_price_snapshot`이 있으면 현재 상품 판매가보다 우선하여 단가 초기값으로 사용. 실제 거래 단가와 과세 여부는 출력 전에 검토.
- 실제 공급자 정보는 인증된 DB에만 별도 등록. 소스 코드에는 사업자번호·주소·전화번호·계좌정보를 포함하지 않음.
- 기존 주문·재고·송장 데이터 변경 없음.
- 확인사항: 관리자 로그인 후 공급자 정보 불러오기·저장, 재로그인 후 동일 정보 표시, 거래명세표 A4 출력, 납품명세표에서 계좌 미표시, 익명 데이터 접근 차단.
